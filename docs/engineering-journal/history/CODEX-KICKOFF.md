## Non-negotiables

- **No new Python.** Not in `scripts/`, not for scratch, not for a debug one-off. **Exactly
  one exception exists and it is enumerated:** the **two** one-off `python -c` invocations in
  `04` M0 — the `resolve_stl()` corpus probe in the owner prerequisite, and the
  synthetic-fixture STL export in work item 6. Both run once from a shell, neither may be
  committed as a `.py` file, and there is no third (`06` §8, `04` §0 rule 2). For everything
  else use a `cargo example`, a `#[test]`, or POSIX shell plus `jq`.
- **Do not edit the existing Python.** Frozen disk artifacts are the oracle; the runnable
  engine is not preserved for its own sake, and each surface deletes at native handoff.
  Reading it is how you learn the algorithms; changing it invalidates the baseline you are
  measured against. A bug you find in it becomes a fix-don't-reproduce item in the Rust
  tests, never a patch to the oracle (`06` §8).
- **Rust only.** TypeScript/bun requires all three of: (1) the concrete blocker named in
  writing — the specific capability, the crates you evaluated, why each fails; (2) a dated
  entry in a **new section at the bottom of `06-conventions.md` titled
  `## Escape-hatch justifications`**, with the blocker and the bounded scope of the
  exception; (3) owner sign-off *before* you write the non-Rust code (`README` §5). Python is
  never an escape hatch.
- **Work the O-5–O-8 critical path in `04`.** A checkpoint is done when
  `cargo test --workspace` passes, `cargo clippy --workspace -- -D warnings` and `cargo fmt`
  are clean, the milestone's gate in `04` passes, the human checkpoint is written into the
  commit message, and the cache-disabled run produces identical reports (`README` §5,
  `06` §10). The gate is as-good-or-better versus the frozen Python baselines — never a
  byte-diff, always measured on files as written to disk. Commit per milestone on `master`.
- **Release-front vocabulary is exact.** The Saturn profile says
  `leading_release_edge = NegativeY` and
  `release_front_sweep_direction = PositiveY`; the front moves `-Y → +Y`. Never
  call that a “-Y sweep” or generic peel direction. The axis input is retained but
  unused by the current measured load-sharing formula.
- **Git safety.** Never `git checkout --`, `git restore`, `git reset --hard`, or
  `git clean`; never force-push; never rewrite published history. Undo your own edits by
  editing (`06` §9).

## How to orchestrate

You conduct; sub-agents do the work. Keep your own context for sequencing, judgment, and
review — do not write substantial code in your main context.

- Use your `model-selection` skill per task to choose model and effort among the models
  available to you (sol / terra / luna): the strongest tier for architecture calls, judging,
  and the hardest debugging; the mid tier as the implementation workhorse; the cheapest tier
  only for mechanical bulk — and anything the cheap tier produces that later work depends on
  gets verified by a stronger model.
- Slice small: one sub-agent per work item, with named files and a self-contained brief.
  Paste the relevant guide excerpts into the brief rather than having every sub-agent re-read
  all seven docs. Many small agents beat one long-running one.
- **Batch-first is law (`06` §1):** gather → one batched call → scatter. A per-item call in a
  hot path is a defect, not a style choice. `rust/geom_kernel/src/queries.rs` is the model to
  copy — none of its queries take a single point. State this explicitly in every
  implementation agent's brief. `04` M3 work item 2 is the worked example:
  `decimate_pipeline.probe()`'s one-point-at-a-time `bvh.find_nearest` loop is the defect,
  not the design.
- Follow the current O-5–O-8 critical path. In particular, protected decimation must land
  before the downstream vertical slice; the former M3/M4 parallelism is historical only.

## Adversarial verification — mandatory, not optional

- Every substantive diff is reviewed by an independent sub-agent that did not write it,
  briefed to find what is WRONG: behavior against the Python oracle, constants against `03`
  (values AND provenance grades), conventions against `06` — and the quality gates re-run,
  not trusted from the author's report.
- Consequential design decisions (type shapes, crate boundaries, algorithm choices beyond
  what `02` already rules) get a proposer AND a challenger, with a strongest-tier judge when
  they disagree. One agent's unreviewed output is never enough.
- Verify by artifact, not by report: run the gates yourself, or in a fresh agent, on the
  files as committed. An author agent claiming its tests pass is not evidence; command output
  is.
- Known traps — brief reviewers to check these specifically:
  - **The three contracts this guide invents, which have no Python precedent**, so nothing
    outside the guide will catch a stub: `PLINTH_THREADS` as the single workspace-wide thread
    variable (`06` §3 — a per-crate variable makes M8's determinism sweep pass vacuously);
    `plinth prepare --no-cache` as the one spelling of cache-off, with no environment-variable
    form (`06` §6 — there is no `PLINTH_CACHE`); and `max_x_group` as a *separate* metric id
    added at M5, with `max_x` keeping its M1 per-arm definition untouched (`04` §3).
    `GEOM_KERNEL_THREADS` is a historical compatibility control deleted at the native
    kernel handoff; `PLINTH_THREADS` is the sole live workspace control and sweep input.
  - **Silent-failure patterns must not be ported.** `resolve_stl()` is the named specimen: it
    never raises, it returns a path that does not exist. So is the fail-not-skip fixture rule
    (`04` M0 work item 9): a test whose required fixture, corpus model or baseline artifact is
    missing **fails with a named reason** — it does not return early and it does not print a
    skip notice and pass. The one sanctioned skip in the tree is `chitubox_io`'s
    `treant_v5_candidate.chitubox`, uncommittable by size.
  - **Emitted files are audited as written to disk** — re-opened from the filesystem, parsed
    fresh, with **no repair pass** between writing and auditing. When the audit fires the fix
    is in the producer, never in the artifact (`06` §6, `05` §6, `04` §0 rule 4).
  - **`plinth-metrics` disk independence is structural**, not duplicate implementation:
    it reopens files, then uses canonical `geom_kernel` and `plinth-mesh`; it does not link
    `plinth-verify`. Check the dependency list, disk provenance, and fixtures.
  - **Never bridge via PyO3 for comparison.** Both sides emit files; `plinth score` compares
    artifacts on disk. A bridge lets one shared kernel bug hide on both sides.

## When to ask the owner (Craig)

Stop and ask — do not guess — when:

- a doc contradiction has no stated precedence;
- a decision the guide explicitly leaves open surfaces;
- a gate cannot be made green without changing what it measures;
- a metric would need a waiver — waivers are owner-signed only;
- anything would require deleting or regenerating a corpus, baseline, or reference file. The
  baseline freeze happens **once**; a physics change requires a documented re-freeze *before*
  comparing, or the comparison measures the physics change rather than the port (`03` §4.4
  step 3, `04` M0 work item 10).

`Measured<T>` has a settled wire policy: exactly `value`, tagged `source`, required
`err`, and `note`. `EvidenceSource` carries a repo record/locator and an
`EvidenceDate::{Exact, OnOrBefore, Unknown}`; generic unknown is only for genuinely
unsourced evidence. Missing, duplicate, or unknown fields are rejected.
`FiniteInterval` uses explicit inclusive/exclusive `BoundKind`; intervals and
categorical values such as `LoadSharing` require explicit `"err": null`. The Saturn
volume/pitch source is known official-vendor evidence, not generic unknown.

**Where decisions get recorded.** The machine-parseable gate and correction tables now
exist in `06-conventions.md`. They are dated and append-only: never edit an existing main
or correction row; append new owner decisions and formal replacements. Signed waivers also go in
`corpus/manifest.json`'s `waivers` array, which stays empty until the owner signs an entry.
