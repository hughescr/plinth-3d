# Owner interview — round 3 (2026-10-29)

**Correction to round 2 notes:** on long/thin fragile parts he does NOT "snap off" supports — any torque risks breaking the part. He cuts them with snips, carefully. Requirement: near fragile features, contacts must be reachable by snips (access/clearance), not merely weak.

1. **Comparison prints.** Yes, plinth vs ChituBox side by side — but only once he judges the plinth output might actually work; he will not spend resin and messy clean-up on something likely to fail. He would import the plinth file into ChituBox and add a ChituBox-supported copy on the same plate (one print run).
2. **Coupons.** Possible, but never ones doomed to fail (that killed most past coupon proposals). Coupons must be credible before they are proposed — cross-model checked first.
3. **Output.** One `.chitubox` per model (easy to mix and match); he merges models onto plates in ChituBox. Goal: all models for a batch end up in one ChituBox file. ChituBox v1.4.0 on macOS (he updates when releases appear). Supports MUST stay separate, editable ChituBox supports (manual edits will sometimes be needed; supports visually distinct from the model when reviewing).
4. **Inputs.** Pre-hollowed models: generally fine. Pre-supported models: he hates them; usually wrong (made for FDM, massively over-supported, or for low-res printers) — some fine, many junk. Kits: e.g. HeroForge splits the mini, its base and a separate familiar into separate STLs; he supports/prints each separately and glues after wash/cure/removal. Units are essentially always mm.
5. **Review.** In ChituBox: rotating/zooming in 3D is unmatched for finding problems; ChituBox's checks (overhang detection etc.) are useful. Text descriptions are hard to match to model details; text paired with rendered images helps.
6. **Speed.** "No worse, ideally better than ChituBox." ChituBox timings on his Mac (auto-orient + "magic support"): Bat Cat Owl 1–2 s; Giant Toad ~3 s; Giant Bat ~5 s; Awakened Tree (treant, "better support") just over 5 min, single-threaded (one core busy, rest idle); hollowing adds a couple of minutes, also single-threaded. ChituBox's UI freezes and its cancel button only acts when the job completes. He expects plinth to use the 12 performance cores, possibly the GPU, and smarter algorithms.
7. **When something can't be supported well:** emit and explain why. Useful outcomes: a manual tweak he can make in ChituBox; a case to bring back to improve the algorithm; or "fundamentally unprintable as is" (then he might split the model into pieces). He believes the minis-to-process set should be straightforward. Some meshes may have defects needing repair (e.g. the treant may have a very thin flap on one foot — possibly a modelling error).
